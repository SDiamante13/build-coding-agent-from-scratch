Lesson 1–3 · the whole idea

An agent is a while loop around one HTTP call

No framework, no orchestration engine. You keep a list of messages, you post it, you append what comes back.

Lesson 4–9 · the part everyone gets wrong

The model never runs anything. It asks you to.

A "tool" is a JSON schema you send, and a JSON request you get back. Reading the file, editing it, running the tests — that is all your code.

How you'll build it

Your coding agent coaches you through it

The repo ships a coach that reads the spec and walks you through it, one small step at a time. Your agent could write all ten lessons in four minutes — and you would learn nothing. Go slow on purpose.

1
Open your agent in the repo and say “coach me”Claude Code, Codex, Gemini CLI or Cursor — each has a shim onto .agents/.
2
It reads the ledger and finds the first Tododocs/specs/README.md — lesson 1 is Done, so you start at 2.
3
It shows you one small change at a timeFile and line, what the step achieves, then why. It stops and waits for you.
4
You make the change — or say “jfdi”Falling behind is fine. “jfdi” and it writes that step for you, and you keep up.
5
The acceptance test has to pass before DoneNo self-assessment. The ledger row only flips when the test is green.
6
Then it shows you what still breaksThe pressure test — which is the next lesson's reason to exist.

Broke it? Nothing is lost.

Every lesson is a tag on the solution branch. Your own work stays exactly where it is.

# a working version of any lesson
git checkout lesson-4-read-file
# or one lesson as a single diff
git diff lesson-3-conversation lesson-4-read-file

Checking your work

# just the lesson you're on
npm test -- lesson-04     # npm start to run it

A fresh clone already passes lesson 1 and fails lesson 2. That failing assertion is your instruction.
